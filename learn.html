    Mission 0 of 5

    Setup Your Environment

    Open the terminal, install Git, and sign in to GitHub. About 15 minutes.

    What is this?

    The terminal is a window where you type instructions to your computer instead of clicking. It looks old-school, but it is how most developers talk to Git, and it is faster than you think.

    Think of it as texting your computer: you type a command, press Enter, and it replies.

    In this mission you will get your computer and your GitHub account ready. It is the longest mission, and everything after it is faster.

    Why it matters

    Git needs to know who you are (so your work has your name on it), and GitHub needs to trust your computer (so nobody else can push changes as you). Doing this once means you never think about it again.

    Step by step

    Which computer are you on?
    1. Open your terminal.

      Press ⌘ Cmd + Space, type Terminal, press Enter.

      Press the Windows key, type PowerShell, and open Windows PowerShell (or Terminal on Windows 11). You do not need “Run as administrator”.

      Press Ctrl + Alt + T, or search your apps for Terminal.

      Don’t worry about breaking things

      Typing a command wrong just gives an error message. Nothing explodes. You can always press Ctrl + C to cancel a command that seems stuck.

    2. Learn three survival commands. Type each one and press Enter.

      pwd = “print working directory”. It tells you which folder you are standing in.

      Terminal
      pwd
      Example output
      /Users/alex
      Example output
      /home/alex
      Example output
      Path
----
C:\Users\alex

      ls = list what is in this folder (on Windows PowerShell, ls works too).

      Terminal
      ls
      Example output
      Desktop    Documents    Downloads    Music    Pictures
      Example output
      Desktop    Documents    Downloads    Music    Pictures
      Example output
          Directory: C:\Users\alex

Mode    LastWriteTime        Length Name
----    -------------        ------ ----
d-r---  03/11/2026  09:12          Desktop
d-r---  03/11/2026  09:12          Documents
d-r---  03/11/2026  09:12          Downloads

      cd = change directory (walk into a folder). cd .. walks back out one level.

      Terminal
      cd Documents
pwd
cd ..
      Tab is your best friend

      Type the first few letters of a folder (like Doc) and press Tab. The terminal completes the name. Press ↑ to bring back the previous command.

    3. Make a workshop folder in your home folder and step into it. All your work today will live here.
      Terminal
      cd ~
mkdir workshop
cd workshop
pwd
      Example output (your path will differ)
      /Users/alex/workshop
      Avoid OneDrive / iCloud / Dropbox folders

      Cloud-synced folders (like Windows “Documents” when OneDrive is on) can corrupt Git projects. That is why we use a plain workshop folder in your home directory.

    4. Is Git installed? Run:
      Terminal
      git --version
      If Git is installed
      git version 2.45.1
      If it is missing (Windows says “'git' is not recognized…”)
      git: command not found

      Got a version number? Skip to the next step. If not, install Git:

      Running git --version on a Mac usually pops up a window offering to install the Command Line Developer Tools. Click Install, wait a few minutes, then run git --version again.

      Prefer Homebrew, the Mac package manager? Install it once (it may ask for your Mac password), then install Git with it:

      Install Homebrew
      /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

      Follow the “Next steps” the installer prints (they add brew to your PATH), then:

      Homebrew
      brew install git

      Easiest way, in PowerShell:

      Terminal
      winget install --id Git.Git -e --source winget

      Then close PowerShell and open it again (so it notices Git), and re-run git --version. No winget? Download the installer from git-scm.com/download/win and click Next through the defaults.

      Pick the line for your distribution:

      Ubuntu / Debian / Mint
      sudo apt update && sudo apt install git
      Fedora
      sudo dnf install git
      Arch
      sudo pacman -S git
    5. Tell Git who you are. Git stamps your name and email on every save (commit). Use the email address of your GitHub account:
      Terminal
      git config --global user.name "Your Nickname"
git config --global user.email "you@example.com"

      Replace the two values with your own. Then double-check:

      Terminal
      git config --global --list
      Example output
      user.name=Alex
user.email=alex@example.com
    6. Create (or log in to) your GitHub account at github.com/signup. Verify your email address. Then type it in the “Your GitHub username” box on this page, and all the commands will fill in your name for you.
    7. Let your computer prove it is you (authentication). The simplest reliable way is the GitHub CLI (gh). It signs you in through your browser and gives Git a secure key. First install it:
      Homebrew
      brew install gh

      No Homebrew? Download the installer from cli.github.com.

      Terminal
      winget install --id GitHub.cli

      Then close and reopen PowerShell. Or download from cli.github.com.

      On recent Ubuntu/Debian, sudo apt install gh often works. Otherwise follow the official Linux install page.

      Now log in:

      Terminal
      gh auth login

      Answer the questions like this (use the arrow keys and Enter): GitHub.com → HTTPS → Yes (authenticate Git) → Login with a web browser. Copy the one-time code, press Enter, paste the code in the browser page that opens, and click Authorize.

      Example output
      ? Where do you use GitHub? GitHub.com
? What is your preferred protocol for Git operations on this host? HTTPS
? Authenticate Git with your GitHub credentials? Yes
? How would you like to authenticate GitHub CLI? Login with a web browser

! First copy your one-time code: ABCD-1234
Press Enter to open github.com in your browser...
✓ Authentication complete.
✓ Configured git protocol
✓ Logged in as alex-123

      Check that it worked:

      Terminal
      gh auth status
      Never type your GitHub password into Git

      GitHub does not accept account passwords for Git commands, and you should never paste your password into a terminal. Use the browser login above (or a Personal Access Token, see troubleshooting).

    Prefer clicking to typing? Do this in GitHub Desktop instead

    Same Git underneath, just buttons. Great if the terminal is blocking you. You can still switch to the terminal steps above any time.

    1. Install GitHub Desktop (macOS and Windows only) from desktop.github.com. It includes Git, so you can skip the Git install and git config steps. Linux users: please use the terminal steps.
    2. Create your GitHub account (the account step above) if you do not have one.
    3. Open GitHub Desktop, choose Sign in to GitHub.com, your browser opens, click Authorize desktop. This replaces gh auth login. No password typing.
    4. It asks for your name and email. Fill them in; you can change them later in Settings / Options, Git.

    Common mistakes & troubleshooting

    “git: command not found” / “git is not recognized”

    Git is not installed, or the terminal was opened before installing. Close the terminal completely and open a new one, then try again. Still failing? Redo the install step for your system.

    “gh: command not found”

    Same idea: close and reopen the terminal after installing. On Windows, if it still fails, sign out and in again, or use the installer from cli.github.com.

    I’m on Windows and prefer Git Bash

    That works too. Git Bash comes with Git for Windows, and all commands in this guide are the same. Just ignore the PowerShell-only lines.

    I don’t want to install gh

    Alternative on Windows: Git for Windows includes Git Credential Manager. The first time you git push, a browser window opens, you sign in to GitHub, and you are done. On macOS/Linux, using gh is the easiest path.

    The browser login doesn’t work (blocked network, etc.)

    Use a Personal Access Token instead: GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token, with Contents: Read and write on your fork. When Git asks for a “password”, paste the token (it is not your password). Ask a facilitator for help. This is the fallback, not the first choice.

    I mistyped my name or email

    Just run the git config --global … command again with the right value. It overwrites the old one.

    Mission 1 of 5

    Understanding Git & GitHub

    The big ideas, with pictures. Then fork the workshop repo. About 10 minutes.

    What is this?

    Version control is a system that remembers every version of your project, like “Version history” in Google Docs, or save points in a video game. If you break something, you can go back.

    Real-world analogy: Instead of saving essay_final.docx, essay_final_v2.docx, essay_REALLY_final.docx, you keep one file, and the system quietly keeps every earlier version, with a note about who changed what and why.

    Git vs GitHub

    GitGitHub
    WhatA programA website / company
    WhereOn your computerOn the internet
    DoesTracks changes to filesStores projects online, lets people collaborate
    Needs internet?NoYes

    Repository, local & remote

    A repository (“repo”) is a project folder that Git is watching, including its whole history. You will have two copies: a local repo on your laptop and a remote repo on GitHub.

    Fork vs clone

    • Fork = make your own copy of someone else’s repo on GitHub (you are not allowed to edit the original directly, but you can edit your fork).
    • Clone = download a repo from GitHub onto your computer.

    We fork first, then clone your fork. Later, a pull request asks the owners to take your changes back.

    Why it matters

    • Undo anything. Every save point is kept.
    • Work together without overwriting each other’s files. Hundreds of people can edit one project.
    • Experiment safely on branches, then keep only what works.
    • It’s the industry standard. Nearly every software team uses it, and employers look at GitHub profiles.

    Step by step: fork the workshop repo

    1. Make sure you are signed in to GitHub, and that you typed your username in the box on this page.
    2. Open the Fork page (opens on GitHub).
    3. Under Owner, pick your own username. Leave the repository name as it is. Click the green Create fork button.
    4. Wait a few seconds. GitHub takes you to your copy. Look at the top-left: it should say {{USERNAME}}/{{REPO}} with “forked from …” underneath.
    5. Copy the address in your browser’s address bar. It should be: {{FORK_PAGE}}. This is the URL of your fork. You’ll use it in the next mission.
    No terminal in this mission

    Forking happens on the GitHub website. From the next mission on, every Git operation happens in your terminal.

    Common mistakes & troubleshooting

    The fork page says “You already have a fork”

    Great, just click to open it. Make sure it’s the fork under your account.

    I forked, but the address doesn’t have my username

    You may be looking at the original repo. Check the URL: it must contain your GitHub username after github.com/. If not, go back to the fork page and try again.

    I can’t see the green “Create fork” button

    Scroll down on the fork page, and make sure you’re logged in (your avatar should be top-right).

    Mission 2 of 5

    Clone Your Repository

    Bring your fork down to your own computer. About 5 minutes.

    What is this?

    Your fork lives on GitHub. To work on it you need a copy on your computer. Downloading a repo is called cloning. Afterwards you have a real local repository that remembers where it came from.

    Why it matters

    All your editing, committing and branching happens in this local copy: fast, offline, and safe. Nothing you do here changes GitHub until you deliberately push.

    Step by step

    1. Go to your workshop folder (from Mission 0):
      Terminal
      cd ~/workshop
    2. Clone your fork. This downloads the project into a new folder named {{REPO}}:
      Terminal
      git clone {{FORK_URL}}
      Example output
      Cloning into '{{REPO}}'...
remote: Enumerating objects: 42, done.
remote: Counting objects: 100% (42/42), done.
Receiving objects: 100% (42/42), 18.20 KiB | 2.02 MiB/s, done.
Resolving deltas: 100% (9/9), done.

      git clone <url> = “download that repository here”.

    3. Step inside the project folder:
      Terminal
      cd {{REPO}}

      cd walks into the folder. Everything from now on happens inside it. Try ls to peek at the files.

    4. Ask Git how things are:
      Terminal
      git status
      Example output
      On branch main
Your branch is up to date with 'origin/main'.

nothing to commit, working tree clean

      git status is the command you will use all the time. It says which branch you’re on and whether you have unsaved changes. “working tree clean” = no changes yet.

    5. See where your copy came from:
      Terminal
      git remote -v
      Example output
      origin  {{FORK_URL}} (fetch)
origin  {{FORK_URL}} (push)

      A remote is a copy of the repo somewhere else. origin is the nickname Git gave to the place you cloned from, your fork. -v means “verbose” (show the addresses).

    You now have a local copy of your fork!

    Your laptop → {{REPO}} folder (local repo) ⇄ GitHub → your fork (origin). The two are connected, but nothing travels between them until you ask.

    Prefer clicking to typing? Do this in GitHub Desktop instead

    Same Git underneath, just buttons. Great if the terminal is blocking you. You can still switch to the terminal steps above any time.

    1. In GitHub Desktop choose File, Clone repository… and open the URL tab.
    2. Paste your fork address: {{FORK_PAGE}}
    3. Pick a local path such as a workshop folder in your home directory (avoid OneDrive/iCloud/Dropbox). Click Clone.
    4. If it asks “How are you planning to use this fork?” choose To contribute to the parent project.
    5. You will see the repo name top-left (Current repository) and Current branch: main. That is your local copy. Clone = git clone.

    Common mistakes & troubleshooting

    “fatal: repository … not found”

    Your username in the URL is probably wrong, or you didn’t fork yet. Check that {{FORK_URL}} opens in your browser. Make sure you typed your username in the box on this page.

    “fatal: destination path … already exists and is not an empty directory”

    You already cloned it. Just cd into the folder, or delete/rename the old folder.

    “fatal: not a git repository” when I run git status

    You’re in the wrong folder. Run pwd; the path must end with {{REPO}}. Use cd ~/workshop/{{REPO}}.

    It asks me for a username and password

    A public repo should clone with no login. If you see a prompt, check the URL for typos, and do gh auth status (Mission 0).

    “Cloning into…” works but I don’t know where the folder went

    It’s inside the folder you were in when you ran the command. Run pwd and ls.

    Mission 3 of 5

    Create a Branch & Make Changes

    Create your profile, then stage and commit it. About 15 minutes.

    What is this?

    A branch is a safe side-road where you can make changes without touching the main version. When you’re happy, you ask to merge it back.

    Analogy: Imagine a shared Google Doc. Instead of typing in the original, you make a copy, write your changes there, and send it to the owner saying “please add this”. That’s a branch + pull request.

    Then you’ll learn the three places a change travels through before it’s saved:

    • Working directory: the normal files on your computer. Edit them freely.
    • Staging area: a waiting room where you choose which changes go into the next save.
    • Commit: a permanent snapshot with a message describing it. Commits make up your local history.

    Why it matters

    Branches keep main clean and let many people work in parallel. Staging + commits let you save meaningful steps (“Add my profile”) instead of one giant blob. This add → commit loop is what you’ll do thousands of times in your career.

    Step by step

    1. Make sure you’re in the project folder (pwd ends with {{REPO}}), then create your branch:
      Terminal
      git switch -c add-my-profile
      Example output
      Switched to a new branch 'add-my-profile'

      git switch -c = “create (-c) a new branch and switch to it”. add-my-profile is just its name. Nothing is changed on GitHub; this branch exists only on your laptop.

    2. Create your profile file by copying the sample. The filename must be your GitHub username + .json:
      Terminal
      cp participants/sample.json participants/{{USERNAME}}.json
      Terminal
      ls participants
      Example output
      {{USERNAME}}.json    sample.json
      Don’t edit sample.json

      It’s the shared template. Only change your file, named after you.

    3. Edit your file. Open it with whichever option works for you:
      Option A · VS Code (any system)
      code participants/{{USERNAME}}.json

      If that says “command not found”, VS Code isn’t on your PATH. Use option B:

      Terminal
      vim participants/{{USERNAME}}.json

      vim is an editor inside the terminal. It starts in view mode, so you cannot type yet. Press i to start typing (-- INSERT -- appears at the bottom), then use the arrow keys to move. When done: press Esc, type :wq and press Enter to save and exit. Made a mess? Press Esc, type :q! and press Enter to quit without saving. Prefer a normal editor? Install VS Code and use the first option.

      Terminal
      vim participants/{{USERNAME}}.json

      vim is an editor inside the terminal. It starts in view mode, so you cannot type yet. Press i to start typing (-- INSERT -- appears at the bottom), then use the arrow keys to move. When done: press Esc, type :wq and press Enter to save and exit. Made a mess? Press Esc, type :q! and press Enter to quit without saving.

      Terminal
      notepad participants/{{USERNAME}}.json

      Notepad opens the file. Edit it, then Ctrl+S and close it.

      Change the three values to your own name, an emoji, and a short fun fact. Keep the quotes, commas and curly braces exactly where they are:

      participants/alex-123.json
      {
  "name": "Alex",
  "emoji": "🚀",
  "fact": "I love building robots!"
}

      Rules: name ≤ 30 characters · exactly one emoji works best · fact ≤ 200 characters · no < or > characters · Save the file when done.

      Emoji shortcut

      macOS: Ctrl+⌘+Space · Windows: Win+. · Linux: copy one from emojipedia.org. Terminal editors can be fussy with emoji; if so, use VS Code.

    4. Ask Git what it sees:
      Terminal
      git status
      Example output
      On branch add-my-profile
Untracked files:
  (use "git add <file>..." to include in what will be committed)
	participants/{{USERNAME}}.json

nothing added to commit but untracked files present (use "git add" to track)

      Git noticed a new file in your working directory but isn’t tracking it yet. “Untracked” = “I see it, but it’s not in the next save”.

    5. Stage your file: put it in the waiting room:
      Terminal
      git add participants/{{USERNAME}}.json
      Terminal
      git status
      Example output
      On branch add-my-profile
Changes to be committed:
  (use "git restore --staged <file>..." to unstage)
	new file:   participants/{{USERNAME}}.json

      It turned from “untracked” to “Changes to be committed”. It’s now in the staging area. Only staged changes get saved in the next commit.

    6. Commit: save the snapshot with a message:
      Terminal
      git commit -m "Add my profile"
      Example output
      [add-my-profile 3f2a9c1] Add my profile
 1 file changed, 5 insertions(+)
 create mode 100644 participants/{{USERNAME}}.json

      -m lets you write the commit message right there. A good message is short and says what you did.

    7. Look at your history:
      Terminal
      git log -1
      Example output
      commit 3f2a9c1d8e7b6a5f4c3b2a1908d7e6f5a4b3c2d1 (HEAD -> add-my-profile)
Author: Alex <alex@example.com>
Date:   Tue Nov 3 10:42:17 2026 +0800

    Add my profile

      git log -1 = “show the latest 1 commit”. That’s your local history. The long code is the commit’s unique ID. This commit exists only on your laptop for now.

    Mission 4 of 5

    Push to GitHub

    Send your commit up to your fork. About 5 minutes.

    What is this?

    So far your commit lives only on your laptop. Pushing uploads your branch’s commits to the remote repository, your fork on GitHub.

    • Remote: a copy of the repo on another computer (here: GitHub).
    • origin: the nickname for your fork’s address (you saw it in git remote -v).
    • Push: send commits from local → remote.
    • Upstream tracking (-u): tells Git “my local add-my-profile is linked to origin/add-my-profile”, so later you can just type git push or git pull.
    • Local vs remote branch: your local branch add-my-profile and the one on GitHub origin/add-my-profile are two separate things that you keep in sync.

    Why it matters

    Pushing is how your work leaves your laptop: it backs it up and makes it possible for a pull request. It’s also the moment GitHub checks that you’re allowed to write to that repo.

    Step by step

    1. Push your branch:
      Terminal
      git push -u origin add-my-profile
      Example output
      Enumerating objects: 5, done.
Counting objects: 100% (5/5), done.
Writing objects: 100% (4/4), 412 bytes | 412.00 KiB/s, done.
Total 4 (delta 1), reused 0 (delta 0)
remote: Create a pull request for 'add-my-profile' on GitHub by visiting:
remote:      https://github.com/{{USERNAME}}/{{REPO}}/pull/new/add-my-profile
To https://github.com/{{USERNAME}}/{{REPO}}.git
 * [new branch]      add-my-profile -> add-my-profile
branch 'add-my-profile' set up to track 'origin/add-my-profile'.

      Read it as: git push send · -u and remember the link · origin to my fork · add-my-profile this branch.

      First push? A login may appear

      If you used gh auth login it should just work. With Git Credential Manager (Windows) a browser window may open: sign in and approve. If Git asks for a “password”, don’t type your GitHub password; see the troubleshooting below.

    2. Check your tracking link locally:
      Terminal
      git branch -vv
      Example output
      * add-my-profile 3f2a9c1 [origin/add-my-profile] Add my profile
  main              a1b2c3d [origin/main] Update README

      [origin/add-my-profile] shows your local branch is linked to its remote twin.

    3. Verify on GitHub: Open my fork’s branches You should see add-my-profile listed. Click it, open the participants folder, and find your JSON file.
    Prefer clicking to typing? Do this in GitHub Desktop instead

    Same Git underneath, just buttons. Great if the terminal is blocking you. You can still switch to the terminal steps above any time.

    1. Click the blue Publish branch button at the top. (= git push -u origin add-my-profile)
    2. If a sign-in window appears, sign in with your GitHub account. The button changes to Fetch origin, which means your branch is on GitHub.
    3. Verify with the Open my fork’s branches button above.

    Common mistakes & troubleshooting

    It asks for my “Username” and “Password”

    GitHub no longer accepts passwords here. Quit with Ctrl+C and run gh auth login (Mission 0). Fallback: type your username, and for the password paste a Personal Access Token (GitHub → Settings → Developer settings → Tokens, with write access to Contents).

    “remote: Permission to … denied” / “fatal: unable to access … 403”

    You’re probably pushing to the original repo instead of your fork. Run git remote -v: the URL must contain your username. If it doesn’t, re-clone from your fork. Or you are logged in as a different GitHub account (gh auth status).

    “fatal: The current branch has no upstream branch”

    You forgot -u origin add-my-profile. Run the full command from step 1.

    “error: src refspec add-my-profile does not match any”

    There’s no such branch or no commit yet. Run git branch and git log -1 to check, and finish Mission 3.

    “Authentication failed” on Windows, repeatedly

    Open Credential Manager → Windows Credentials → remove any git:https://github.com entries, then push again and sign in through the browser window.

    “remote: Repository not found”

    Check you forked, and that the repo name/username in git remote -v is right.

    The push seems frozen

    Look for a browser window or a prompt waiting for you. If it’s truly stuck, Ctrl+C and try again.

    Mission 5 of 5

    Open a Pull Request & Go Live

    Ask to join the wall, and watch it appear. About 10 minutes.

    What is this?

    Your changes are on your fork. A pull request (PR) is a polite message to the original project: “I made some changes. Would you like to pull them in?”

    • Pull request: a proposal to merge your branch into someone else’s repo.
    • Code review: a person (here, a facilitator) looks at what you changed and approves or asks for tweaks. Tests run automatically, too.
    • Merge: your commit becomes part of the official project.

    Why it matters

    This is how nearly all open-source (and most professional) software is built. Nobody pushes straight to the shared project; everyone proposes changes, and teammates review them. You’re about to do exactly that.

    Step by step

    1. Open the pull request page: Start my pull request
      (Or open your fork and click the yellow “Compare & pull request” banner.)
    2. Check the direction at the top. It should read: base repository: {{OWNER}}/{{REPO}} · base: main ← head repository: {{USERNAME}}/{{REPO}} · compare: add-my-profile.
    3. Write a short title and description. A template appears. Fill in your username and tick the boxes. Example title: Add Alex’s profile. Add a friendly sentence, e.g. “Hi! I’m new to Git. This adds my fun fact.”
    4. Click “Create pull request”. You’ve opened a PR! Scroll down to see the Files changed tab: it shows exactly your one new file.
    5. Wait for the checks and a review. An automatic check validates your JSON (a green is good; a red explains what to fix). A facilitator will review and click Merge. Put up your hand or watch for the purple “Merged” label.
    6. Wait ~1–3 minutes after the merge. GitHub rebuilds the website. Then open the Community Wall and press Refresh: Go to the Wall
    7. Find your card! If you typed your username into the box on this page, your card will say “That’s you! ”.
    Merged but not on the wall yet?

    Be patient: GitHub Pages needs a minute or two to publish. Hard-refresh with Ctrl+Shift+R (⌘+Shift+R on Mac). Still nothing after 5 minutes? Ask a facilitator to check the Actions tab.

    Need to change something after opening the PR?

    Just edit your file locally, then run git add, git commit and git push again (the last one needs no extras). The PR updates itself!

    Prefer clicking to typing? Do this in GitHub Desktop instead

    Same Git underneath, just buttons. Great if the terminal is blocking you. You can still switch to the terminal steps above any time.

    In GitHub Desktop, after publishing, click Create Pull Request (at the top, or under Branch, Create Pull Request). It opens the same GitHub page in your browser; then follow steps 2–7 above. Check the base repository is the original workshop repo, not your fork.

    Need to change your file later? Edit it, commit in the Changes tab, then click Push origin.

    Common mistakes & troubleshooting

    The base repository is my own fork

    Click the base repository drop-down and choose the original workshop repo ({{OWNER}}/{{REPO}}). Otherwise you’d be sending the PR to yourself.

    I don’t see “Compare & pull request”

    Use the blue button above, or on your fork choose Contribute → Open pull request.

    The check failed with a red

    Click Details to read the message. Usually it’s a JSON typo (missing comma/quote) or a wrong filename. Fix the file locally, git add → git commit -m "Fix profile" → git push.

    The check says “Waiting for approval” / “Approve and run”

    GitHub holds workflows from first-time contributors. A facilitator will approve it; you don’t need to do anything.

    “This branch has conflicts”

    Rare here, since everyone adds a different file. Ask a facilitator for help.

    I opened two pull requests by mistake

    No harm done. Click “Close pull request” on the extra one.
