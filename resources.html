Git cheat sheet

The commands from today, one sentence each. Open the printable one-page version (use your browser’s Print → Save as PDF).

Setup

git --versionCheck that Git is installed.
git config --global user.name "Your Name"Set the name shown on your commits.
git config --global user.email "you@example.com"Set the email shown on your commits.

Get a project

git clone <repo-url>Download a repository to your computer.
git remote -vShow which online repositories this one is linked to.

Look around

git statusShow what changed and what is staged.
git log --onelineShow the history, one short line per commit.

Save your work

git switch -c <branch-name>Create a new branch and switch to it.
git add <file>Stage a file so it goes into the next commit.
git commit -m "message"Save a snapshot of the staged files with a note.

Share

git push -u origin <branch-name>Upload your branch to GitHub and remember the link.
git pullDownload and merge new changes from GitHub.

Troubleshooting

Most errors are typos or being in the wrong folder. Read the message; it usually tells you what’s wrong.

git: command not found / “not recognized”

Git isn’t installed or the terminal needs restarting. Install Git (Mission 0), then close and reopen the terminal.

“Author identity unknown”

Set your name and email: git config --global user.name "Name" and git config --global user.email "you@example.com", then commit again.

“fatal: not a git repository”

You’re in the wrong folder. cd into the project folder (the one containing the hidden .git folder). pwd shows where you are.

Stuck in a strange editor (Vim) after git commit

Press Esc, type :q!, press Enter. Next time use git commit -m "message".

Asked for username/password when pushing

GitHub doesn’t accept passwords. Run gh auth login (browser sign-in), or use a Personal Access Token as the password.

“Permission denied” / 403 when pushing

You’re pushing to the original repo, or logged in as the wrong account. git remote -v must show your fork; gh auth status shows your account.

“The current branch has no upstream branch”

Use git push -u origin <branch-name> the first time.

“Updates were rejected because the remote contains work that you do not have”

Your branch on GitHub has commits you don’t have locally. Run git pull, then git push. If it opens an editor for a merge message, save and close it.

“nothing to commit, working tree clean” but I just edited a file

Your editor probably didn’t save, or you edited a file outside the project folder. Save (Ctrl/Cmd+S) and run git status again.

My pull request check is red

Open Details and read the message: usually a JSON typo (missing quote/comma), wrong filename (must be your-username.json), or extra files changed. Fix, git add, git commit, git push.

I’m merged but not on the wall

The site rebuilds after a merge, which takes 1–3 minutes. Hard refresh (Ctrl/Cmd+Shift+R). Still missing? Ask a facilitator to look at the Actions tab.

Windows: PowerShell says running scripts is disabled

You don’t need scripts for this workshop. If you see this after installing something, ignore it or ask a facilitator.

I want to start over

Delete the cloned folder (carefully!) and run git clone again from Mission 2. Your fork on GitHub is unaffected.

Still stuck?

Raise your hand, or copy the exact error text and show a facilitator. Nobody minds, we’ve all been there.

Bonus missions

Finished early? These are optional and intermediate. Don’t worry if you skip them. Type your username in the box on the Learn page to fill in the commands.

Intermediate · optional Bonus 1

Edit your profile and make another commit

Real projects are many small commits. Make a second one.

  1. Open your profile (code participants/{{USERNAME}}.json, or vim/notepad as in Mission 3) and change your fun fact. Save.
  2. Check, stage and commit:
    Terminal
    git status
git add participants/{{USERNAME}}.json
git commit -m "Update my fun fact"
    Terminal
    git log --oneline
    Example output
    9d8c7b6 (HEAD -> add-my-profile) Update my fun fact
3f2a9c1 Add my profile
a1b2c3d Update README
  3. Push it: git push (no extra words needed, thanks to -u). If your PR is still open, it updates itself.
Already merged?

If a facilitator already merged your PR, do Bonus 3 first, then start a fresh branch with git switch -c update-my-fact, so you don’t get a conflict.

Intermediate · optional Bonus 2

Inspect changes with git diff

See exactly what changed, line by line, before you commit.

  1. Edit your JSON file (change the emoji) but don’t stage it yet. Then:
    Terminal
    git diff
    Example output
    diff --git a/participants/{{USERNAME}}.json b/participants/{{USERNAME}}.json
--- a/participants/{{USERNAME}}.json
+++ b/participants/{{USERNAME}}.json
@@ -1,5 +1,5 @@
 {
   "name": "Alex",
-  "emoji": "🚀",
+  "emoji": "🦊",
   "fact": "I love building robots!"
 }

    Lines starting with - were removed, + were added. If the output fills the screen, press Space to scroll and q to quit.

  2. Stage it and compare again:
    Terminal
    git add participants/{{USERNAME}}.json
git diff --staged

    git diff = “changes not staged yet”. git diff --staged = “changes that will go into the next commit”.

  3. Compare two branches: git diff main shows how your current branch differs from main. (Undo the experiment with git restore --staged participants/{{USERNAME}}.json then git restore participants/{{USERNAME}}.json.)
Intermediate · optional Bonus 3

Sync with upstream using git pull

Get everyone else’s merged work onto your computer.

Your fork doesn’t automatically get new commits from the original project (the upstream). Let’s fetch them, for example everyone else’s merged profiles.

  1. Tell Git about the original repo once:
    Terminal
    git remote add upstream {{UPSTREAM_URL}}.git
git remote -v
    Example output
    origin    {{FORK_URL}} (fetch)
origin    {{FORK_URL}} (push)
upstream  {{UPSTREAM_URL}}.git (fetch)
upstream  {{UPSTREAM_URL}}.git (push)
  2. Update your local main:
    Terminal
    git switch main
git pull upstream main
    Example output
    From {{UPSTREAM_URL}}
 * branch            main       -> FETCH_HEAD
Updating a1b2c3d..e4f5a6b
Fast-forward
 participants/sam-dev.json  | 5 +++++
 participants/mia-codes.json | 5 +++++
 2 files changed, 10 insertions(+)

    git pull = download new commits (fetch) and combine them with yours (merge). “Already up to date” just means nothing new has been merged yet.

  3. Optionally update your fork on GitHub too:
    Terminal
    git push origin main
  4. Run ls participants. You’ll see other people’s files appear on your computer!
Intermediate · optional Bonus 4

Two branches, one folder

Create two branches and switch between them in a throwaway repo.

Safe playground: we create a brand-new, throwaway repository so we don’t touch your real fork.

  1. Create the practice repo with a first commit:
    Terminal
    cd ~/workshop
mkdir branch-practice
cd branch-practice
git init -b main
    Terminal
    git commit --allow-empty -m "Start practice"

    (--allow-empty lets you commit with no files, handy for practice.)

  2. Create branch-a and add a file to it:
    Terminal
    git switch -c branch-a
    Terminal
    touch a.txt
    Terminal
    touch a.txt
    Terminal
    New-Item a.txt -ItemType File
    Terminal
    git add a.txt
git commit -m "Add a.txt"
  3. Back to main, create branch-b with a different file:
    Terminal
    git switch main
git switch -c branch-b
    Terminal
    touch b.txt
    Terminal
    touch b.txt
    Terminal
    New-Item b.txt -ItemType File
    Terminal
    git add b.txt
git commit -m "Add b.txt"
  4. Hop between them and watch the files appear and vanish:
    Terminal
    git switch branch-a
ls
git switch branch-b
ls
git branch
    Example output
    Switched to branch 'branch-a'
a.txt
Switched to branch 'branch-b'
b.txt
  branch-a
* branch-b
  main

    Each branch is its own timeline. See them all: git log --oneline --graph --all.

Intermediate · optional Bonus 5

Resolve a merge conflict (practice repo)

Create a conflict on purpose and fix it. Zero risk to the workshop repo.

A merge conflict happens when two branches change the same line, so Git asks you to decide. It sounds scary but it is just a text file with markers. We’ll make one on purpose, in a disposable repo.

  1. Create a practice repo:
    Terminal
    cd ~/workshop
mkdir conflict-practice
cd conflict-practice
git init -b main
    Create story.txt and commit it:
    Terminal
    printf 'Roses are red\n' > story.txt
    Terminal
    printf 'Roses are red\n' > story.txt
    Terminal
    Set-Content story.txt "Roses are red"
    Terminal
    git add story.txt
git commit -m "Add story"
  2. On a branch, change the line:
    Terminal
    git switch -c feature
    Terminal
    printf 'Roses are scarlet\n' > story.txt
    Terminal
    printf 'Roses are scarlet\n' > story.txt
    Terminal
    Set-Content story.txt "Roses are scarlet"
    Terminal
    git commit -am "Scarlet roses"
  3. Back on main, change the same line differently:
    Terminal
    git switch main
    Terminal
    printf 'Roses are crimson\n' > story.txt
    Terminal
    printf 'Roses are crimson\n' > story.txt
    Terminal
    Set-Content story.txt "Roses are crimson"
    Terminal
    git commit -am "Crimson roses"
  4. Merge, and meet the conflict:
    Terminal
    git merge feature
    Example output
    Auto-merging story.txt
CONFLICT (content): Merge conflict in story.txt
Automatic merge failed; fix conflicts and then commit the result.
  5. Open story.txt (code story.txt, vim story.txt or notepad story.txt). It looks like this:
    story.txt
    <<<<<<< HEAD
Roses are crimson
=======
Roses are scarlet
>>>>>>> feature

    Above ======= is your side (main); below is the other side (feature). Edit the file to the final text you want, for example Roses are crimson and scarlet, and delete the three marker lines (<<<<<<<, =======, >>>>>>>). Save.

  6. Tell Git it’s resolved:
    Terminal
    git add story.txt
git commit -m "Resolve conflict"
    Terminal
    git log --oneline --graph
    Example output
    *   7c6b5a4 (HEAD -> main) Resolve conflict
|\  
| * 2b3c4d5 (feature) Scarlet roses
* | 8e9f0a1 Crimson roses
|/  
* 1a2b3c4 Add story
Changed your mind mid-conflict?

Run git merge --abort to go back to before the merge.
